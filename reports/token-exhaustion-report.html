심층 분석: 361바이트 불일치가 40만 토큰 과금으로 증폭된 4단계 과정

1단계: Claude Code의 시스템 리마인더 갱신
Claude Code는 매 턴마다 현재 작업 환경(현재 시각, 작업 디렉터리의 git 상태, 터미널 환경 등)을 최신화하여 프롬프트 말미에 <system-reminder> 형태로 주입합니다. 이 과정에서 직전 턴에 전송되었던 인덱스 290번 메시지의 내용이 361바이트 크기의 새로운 시스템 텍스트로 치환되었습니다.
2단계: Meridian의 엄격한 해시 검증과 구제 실패
Meridian의 세션 검증 엔진(verifyLineage)은 이전 대화 배열의 해시(lineageHash)가 완벽히 일치해야만 기존 SDK 세션을 이어받습니다. 직전 메시지의 tool_result가 누적된 경우에는 부분 재개(boundary continuation)를 허용하는 예외 로직이 있으나, 이번 불일치는 시스템 메시지(system[string]) 변경이었기 때문에 구제되지 못하고 modified-history(이력 변조)로 판정되었습니다.
3단계: 기존 세션 폐기 및 40만 토큰 전액 Replay 트리거
이력이 오염되었다고 판단한 Meridian은 기존 Claude Code 백그라운드 세션 포인터를 즉시 폐기하고, 0번부터 290번까지의 대화 40만 토큰 전체를 완전히 새로운 세션에 처음부터 재생(Starting fresh replay)하도록 지시했습니다. 앞선 290개 메시지(40만 토큰)가 완전히 일치했음에도 불구하고 캐시 참조 연결 고리가 끊어졌습니다.
4단계: Anthropic API의 1.25배 신규 캐시 작성 과금 폭탄
Anthropic 프롬프트 캐싱 구조상, 세션이 끊겨 새로 들어온 40만 토큰은 '캐시 읽기(Cache Read)'가 아닌 '신규 캐시 생성(Cache Creation)'으로 처리됩니다. 캐시 생성 토큰은 일반 입력의 1.25배 가중치가 부과되므로, 361바이트 차이 하나 때문에 1회 턴당 45만~50만 토큰 상당의 세션 쿼터가 일시에 증발했습니다. 이것이 6번 반복되면서 8분 만에 한도가 100% 소진된 것입니다.
